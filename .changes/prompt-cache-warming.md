- Prompt-cache warming (the pi `CacheWarmer` port): a model whose catalog entry carries `promptCache` lifetimes keeps its prompt-cache entry alive across think pauses, refreshing at `min(90% of the TTL, TTL − 10 s)` with a one-token replay of the request exactly as sent — only when the expected saving is at least $0.05, never for Anthropic budget-keyed thinking requests whose replay would change the cache key, and always off the turn path (a hung provider never delays a turn).
- New `cacheWarming` setting (`off` | `streaming` | `idle`, default `off` — warming is opt-in because it spends money; read from global settings only): `streaming` warms only while the agent run is active; `idle` continues for up to 30 minutes after it settles.
- Successful refreshes append a `type: "usage"` session row (`kind: "cache_warm"`) so resumed sessions show what warming spent, and count into session telemetry (`cache_warm_refresh_count`; refresh content never uploads).
- Session requests now carry the session's routing id on the wire (TS parity): providers key their prompt caches per session, and OpenAI-compatible providers send the same `prompt_cache_key`/`prompt_cache_retention` fields the TS product sends.
- Models the catalog gives no `promptCache` lifetimes use built-in defaults when they are served by Anthropic's or OpenAI's own endpoints (5 minutes; 1 hour for Anthropic and 24 hours for OpenAI under long retention, exactly when the request asks for it), so warming runs before the catalog carries the field; catalog values always win.
- The replay-safety check now recognizes Anthropic models by their real API id (`anthropic-messages`), so budget-keyed thinking requests are never replayed.
